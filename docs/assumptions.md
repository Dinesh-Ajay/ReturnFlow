# ReturnFlow Architectural & Domain Assumptions

This document records all engineering and domain assumptions adopted in the implementation of **ReturnFlow**.

---

## 1. Temporal Reference Frame
- **Reference Evaluation Date:** The application adopts `2026-10-22` as the deterministic `REFERENCE_DATE` across all derived operational calculations (e.g. days outstanding, overdue classification, loss thresholds).
- **Timezone Standardization:** All database records and API representations store and calculate timestamps in **UTC** (`timezone.utc`).
- **Dispatch Simulation Window:** Generated shipments and dispatches are distributed over a 90-day window preceding `REFERENCE_DATE` (July 2026 – October 2026) to generate realistic lifecycle distributions across completed, in-transit, overdue, and lost states.

---

## 2. Identifier Schemes
- **Asset ID Pattern:** Deterministic zero-padded 7-digit pattern: `ASSET-0000001` through `ASSET-0020000`.
- **Shipment ID Pattern:** Year-prefixed 6-digit counter: `SHP-2026-000001`.
- **Return Authorization ID Pattern:** Year-prefixed 6-digit counter: `RMA-2026-000001`.
- **Custody Event ID Pattern:** Per-asset counter zero-padded to 6 digits: `CUST-<asset_id>-000001` (e.g. `CUST-ASSET-0000001-000001`).
- **Inspection & Repair ID Patterns:** Year-prefixed: `INSP-2026-000001` and `REP-2026-000001`.
- **Anomaly Identifier Pattern:** Injected anomalies follow `ANOM-000001`; detected runtime findings follow `DET-000001`.

---

## 3. Financial & Accounting Model
- **Monetary Storage:** All monetary balances use `DECIMAL(12, 2)` to eliminate floating-point rounding inaccuracies.
- **Liability Conventions:** A positive deposit ledger entry (`DEPOSIT_CHARGE`) indicates money collected by the fleet manager and held as a liability owed to the customer upon return.
- **Refund Conventions:** A negative deposit ledger entry (`DEPOSIT_REFUND`) reflects money credited back to the customer.
- **Damage Deductions:** A positive damage charge (`DAMAGE_CHARGE`) offsets the deposit liability before issuing partial refunds.
- **Reconciliation Invariant:** An asset portfolio is considered financially reconciled when total collected deposits equal or exceed the sum of refunds, damage charges, and loss charges.

---

## 4. Anomaly Injection Strategy
- Baseline records generated by `MasterGenerator` and `TransactionGenerator` are guaranteed 100% referentially and logically sound.
- The 5 mandatory anomaly scenarios are injected by `AnomalyInjector` with explicit ground-truth metadata in `data/ground_truth/ground_truth.json` and `data/ground_truth/ground_truth.csv`:
  - `SIMULTANEOUS_LOCATIONS` (Critical) -> Expected decision: `FLAG_FOR_INVESTIGATION`
  - `RETURN_BEFORE_DISPATCH` (Critical) -> Expected decision: `INVALID_LIFECYCLE_TRANSITION`
  - `DUPLICATE_REFUND` (High) -> Expected decision: `DUPLICATE_REFUND`
  - `REPAIR_WITHOUT_INSPECTION` (High) -> Expected decision: `REPAIR_WITHOUT_INSPECTION`
  - `MISSING_CUSTODY_ACTOR` (Medium) -> Expected decision: `MISSING_CUSTODY_ACTOR`
- Injected count: 2 instances per scenario (10 total) for the starter profile, and 10 instances per scenario (50 total) for the full profile.
- Detectors evaluate data independently and do NOT consume ground-truth files during detection execution.

---

## 5. Storage Engine & Database Portability
- Primary relational storage is MySQL 8.0+ / 9.1 with `InnoDB` engine, `utf8mb4` character set, and `utf8mb4_unicode_ci` collation.
- All SQLAlchemy models and database queries avoid dialect-specific non-standard syntax, providing full portability to PostgreSQL / Supabase simply by updating `DATABASE_URL`.
